# Install

## Homebrew

```sh
brew install --cask Allan-Nava/tap/pqprobe
```

A **cask**, so what arrives is the prebuilt binary from the release — no Go, no
compile. It is generated by goreleaser on every tag and pushed to
[Allan-Nava/homebrew-tap](https://github.com/Allan-Nava/homebrew-tap), the same
tap the sibling tools use.

The binary is unsigned, so the cask strips macOS's quarantine attribute in a
postflight hook: without that the install would succeed and Gatekeeper would
refuse to run it. The `Brew` workflow installs the cask on arm64 and Intel after
every release and checks exactly that, because an install nobody performs proves
nothing.

A prerelease tag (`v1.0.0-rc.1`) publishes its archives and **not** its cask:
`brew install` should never hand out a release candidate.

## Go

```sh
go install github.com/Allan-Nava/pqprobe/cmd/pqprobe@latest
```

Go 1.25 or newer. The hybrid group `X25519MLKEM768` comes from the standard
library, which is why the tool has no dependencies at all.

## From source

```sh
git clone https://github.com/Allan-Nava/pqprobe
cd pqprobe
go build -o pqprobe ./cmd/pqprobe
./pqprobe probe example.com
```

## Docker

The published image is `scratch` plus the binary and the CA bundle — no shell,
nothing else to reason about when it is pointed at production endpoints. Every
release pushes it multi-arch (amd64 and arm64) with a provenance attestation,
and the workflow smoke-tests the pushed image before the release is done:

```sh
docker pull ghcr.io/allan-nava/pqprobe:0.3.0
docker run --rm ghcr.io/allan-nava/pqprobe:0.3.0 probe example.com
```

`:latest` follows the newest release. Pin the version for anything scheduled —
a probe pointed at production should be pinned deliberately.

To build it yourself:

```sh
docker build -t pqprobe .
docker run --rm pqprobe probe example.com
```

## What it needs

Outbound TCP to the endpoints being probed, and nothing else. No agent on the
targets, no credentials, no configuration file.
